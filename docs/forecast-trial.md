# 老款数仓预测试算

## 使用方式

试算命令直接读取本项目配置的数仓。`--snapshot` 按需求表快照中的SKU查询，范围与服务填充一致；`--style` 用于按款号读取全部SKU的独立诊断。输出本地计算证据。它不访问飞书、不写Redis、不创建文件副本、不发送通知，也不受服务填充开关控制。

```bash
uv run stocking-sheet-sync-forecast \
  --style KQ25073 \
  --as-of 2026-09-12 \
  --output artifacts/forecast-trial
```

需求表范围试算使用 `--snapshot artifacts/表格目录/sheet-snapshot.json`，与 `--style` 二选一。多个款式可重复传入 `--style`。日期必须显式指定。配置分别为：

- `.env` 的 `WAREHOUSE_*`：数仓连接。
- `config/sales-sources.toml`：平台出库明细来源和筛选。
- `config/forecast-sources.toml`：整款主数据、京东每日快照及全公司来源状态。
- `config/forecast.toml`：季节和需求分配规则。
- `config/sheet-layout.toml`：款式年份分类规则。

输出 `forecast.json` 保存主数据、窗口、逐平台来源结果、异常及分配过程；`forecast.csv` 保存逐SKU的当前30天、去年同期30天、去年后续周期、占比、取整和最终试算量。错误项的预估为空。返回码0表示全部可计算，2表示报告中有待核对项，1表示运行或配置失败。

`ready` 表示该平台整款试算通过当前校验，不代表目标表可以直接写入。表内商品身份、人工值和公式保护属于写入阶段的独立检查。

## 数据校验

商品主数据按所选查询范围投影去重，保留SKU、款号、名称、规格和标签。相同SKU出现不同身份或标签、请求的不同款式共享SKU、季节冲突时，该款暂停计算。需求表模式仅查询表内SKU，并按这些SKU分款汇总、分配。按款号模式用于诊断该款全部主数据SKU。

拼多多、唯品、京东POP、猫超沿用销售出库明细筛选和业务主键去重，并分别检查三段历史窗口逐日覆盖。在整个平台窗口均有出库记录且主数据有效的前提下，SKU无出库记录按零处理。每日存在记录只能证明日期有数据，不能证明上游同步在日内绝对完整。

京东自营使用 `bwd_rpa_jd_inventory_product_detail.outbound_yesterday`，业务日按 `dt` 读取。逐SKU每天必须恰有一条有效记录；缺日、同日多记录、空平台SKU标识、非法数量均暂停该款该平台计算。两个30天窗口还要求日值累计等于窗口末日的 `outbound_30d`，不一致时保留两者作为证据。去年后续周期累加日值，不累加滚动快照。

全公司范围保留待确认。触发“SKU少于10且平台整款当前30天少于20”时，返回 `company_scope_pending_confirmation`，不采用未经确认的公司占比。其他平台项可独立试算。

## 京东日期证据与限制

四款样本2025-08-01至2026-09-12读取了26,309条日记录，覆盖77个条码，样本内无同条码同日重复。9月快照通常于 `dt` 次日创建，亦有延迟创建的记录。

样本882条月初记录中，月累计出库全部等于当日 `outbound_yesterday`。按 `dt` 原日期对齐，7天累计25,874次检查中25,769次相等，30天累计24,310次检查中23,851次相等；前后错移一天的相等比例明显更低。这些数据支持 `dt` 为业务日的判断，字段注释只有“时间”，尚无上游ETL定义作为独立证明。滚动对账差异的原因未确认，程序对差异保持待核对状态。

全店同日记录数多于不同条码数，说明样本之外存在条码不唯一，日读取器必须持续检查每次输入，不能依赖本次样本结论。

## 全公司口径待确认

2026-08-13至2026-09-11的销售出库中包含部门“不计入”及空部门。“不计入”下有京东自营拉货、园区补货等记录，不能直接与京东终端销量相加。按公司、出库主单、出库子单、SKU分组，有13,885组同时出现在不同 `data_source` 中，跨来源直接相加有重复风险；仅这一组键相同也不足以证明可以跨系统合并，需核验来源定义。

“有明确业务部门且不属于不计入的销售出库，再加京东自营终端销量”是待讨论方案，尚未确认。该问题按业务要求保留，运行试算不读取或使用全公司兜底量。

## 表格填充

服务内 `FILL_FORECAST_ENABLED` 已接入表内SKU查询和身份核对、历史及公式预估列结构、计算数量写入和回读校验，保持人工需求、公式和其他部门内容。全公司范围、主数据冲突及京东差异项有明确依据后才能计算对应项。详见 [公式预估填充](forecast-fill.md)。本地试算命令独立可用。
