# 市场部结构准备

`stocking-sheet-sync-layout` 读取工作表，按款式编码识别新品或老品，输出市场部现有字段、目标字段及调整建议。它不连接数仓，不填充销量或预测需求，不执行表头写入。库存、其他部门、需求汇总和采购信息均不参与调整。

## 配置

在项目根目录运行。`config/sales-sources.toml` 提供商品字段和平台表头别名；`config/sheet-layout.toml` 提供分类规则、平台顺序、标准标题及历史区间表头。

当前配置从款式编码 `KQ` 后提取两位年份：`KQ26` 为新品，早于 26 的年份为老品；更晚年份或无法识别的款式进入待核对。一张表可包含多个同类款式，新品与老品混合时需要先明确共用表头方案。

新品按以下顺序排列，共 10 列：

| 近30天销量 | 需求数量 |
| --- | --- |
| 唯品近30天 | 唯品会 |
| 自营近30天 | 京东自营 |
| 拼多多近30天 | 拼多多 |
| 猫超近30天 | 天猫超市 |
| 京东POP近30天 | 京东POP |

已有需求列按平台别名识别，保留原表头名称及该列的人工数量。缺少销量列时，在对应需求列前插入销量列。生成的近30天表头使用连续文本，例如 `唯品近30天`。

## 初始模板

[下单模板](https://kocotree.feishu.cn/sheets/KLyfsPjNxh3VI6tmLwgck3CInH2)是接收下单需求的主要输入样式。该模板已包含市场部合并表头和五个平台需求列，商品款号及编码用于判断适用规则和匹配数据。

模板新品的列映射如下，插入位置按实际表头识别：

| 平台 | 原需求列 | 新增销量列 | 调整后需求列 |
| --- | --- | --- | --- |
| 唯品会 | N | N | O |
| 京东自营 | O | P | Q |
| 拼多多 | P | R | S |
| 天猫超市 | Q | T | U |
| 京东POP | R | V | W |

市场部合并表头由 `N2:R2` 扩展为 `N2:W2`。五个需求列整列保留，只补齐五个销量列；其他部门、库存和汇总信息不属于编辑范围。

## 老品区间

老品保持同一平台顺序，每个平台依次为「往年区间销量、近30天销量、需求数量」，拼多多另有「往年实发－实退」，共 16 列。每个平台保留自己已有的区间表头；拼多多实发与实发减实退的区间需要一致。

缺少历史区间列时，优先取同平台其他历史列中的区间标签；没有可用区间时，可在结构配置的 `[history_periods]` 中按平台填写，例如 `vip = "25.9-10月"`。这些文本只用于结构预览，不自动换算数仓查询日期。已有区间与显式配置冲突时，报告待核对。

## 识别边界

- 按三行表头、市场部分组和实际列坐标识别，不固定列字母或工作表名称。
- 唯品会与唯品、天猫超市与猫超等别名由平台配置提供；匹配时统一空格、全半角和大小写。
- 已知市场部字段紧邻分组，且上方分类单元格为空、未归入其他合并分组时，可建议扩展市场部合并表头。
- 近 7 天、其他自定义字段、新品中的指定区间销量、重复字段、商品编码异常或「市场部其它」合并平台列会阻止生成操作清单，原内容保留供核对。
- 现有数量（包括零）、公式和表尾合计都不写入。报告统计商品行已填单元格数，方便核对保留情况。

## 使用

线上模式依赖已登录用户身份的 `lark-cli`。先查工作簿，使用实际返回的工作表 ID：

```bash
lark-cli sheets +workbook-info --spreadsheet-token '<表格 token>' --as user
uv run stocking-sheet-sync-layout \
  --spreadsheet-token '<表格 token>' \
  --sheet-id '<工作表 ID>' \
  --output artifacts/layout-preview
```

完整快照可用于离线预览，此模式不需要飞书登录或数仓凭证：

```bash
uv run stocking-sheet-sync-layout \
  --snapshot artifacts/layout-preview/sheet-snapshot.json \
  --output artifacts/layout-offline
```

可用 `--source-config` 和 `--layout-config` 显式选择其他配置文件。

输出包括：

- `layout-preview.md`：逐列目标及中文调整说明。
- `layout-preview.json`：分类、原列到目标列的映射、现有值计数、建议和问题。
- `sheet-snapshot.json`：完整值、公式、合并范围及读取版本。

状态 `ready` 表示结构符合规则；`changes_proposed` 表示已生成结构建议；`needs_review` 表示存在待核对事项，操作清单为空。命令退出码 0 表示报告生成成功，读取或配置失败返回 1。

操作清单是结构层面的建议，不是可以直接提交给飞书的批量请求。原列坐标对应快照，目标列对应拟议结构；插入和移动的位置按操作顺序解释。实际补列命令会根据最新版本检查合并、样式和行列变化。插入市场部列会让右侧列位置顺移；其他部门内容及汇总公式的编辑不在本功能范围。

## 新品实际补列

`stocking-sheet-sync-layout-apply` 适用于五个平台需求列齐全、平台顺序明确的新品表。它在各需求列前补销量列，复制对应需求列的字体、对齐、边框等格式，设置销量标题与列宽，并合并市场部分组。原需求数量随列移动；新增销量列的商品行和合计行保持空白。

默认仅生成请求并进行接口预检。先在测试副本运行：

```bash
uv run stocking-sheet-sync-layout-apply \
  --spreadsheet-token '<测试副本 token>' \
  --sheet-id '<工作表 ID>' \
  --output artifacts/layout-apply-preview
```

查看 `before.json` 中的 `revision` 和 `request.json` 中的操作后，指定该版本执行，例如读取版本为 0 时：

```bash
uv run stocking-sheet-sync-layout-apply \
  --spreadsheet-token '<测试副本 token>' \
  --sheet-id '<工作表 ID>' \
  --apply --expected-revision 0 \
  --output artifacts/layout-applied
```

命令在提交前再次核对版本，以单个批量请求执行，并回读完整工作表。校验包括原单元格的值与格式、公式及计算结果、新列样式与空值、行高和合并范围。飞书会随插列自动调整公式引用，调整记录保存在核验结果中。请在表格无人同时编辑时执行；版本预检不提供并发写入锁。

执行目录保留 `before.json`、`request.json`、`dry-run.json`、`response.json`、`after.json` 与 `result.json`。出错时保存 `error.json`，需要结合前后快照核对实际状态。网络异常或核验失败均不自动重试写入。再次运行时传入当前版本；结构符合规则则返回 `status: unchanged`，不提交批量请求。

执行命令只支持新品补列及标准表头、分组整理。老品、需要移动平台列、缺少需求列或存在识别问题时停止并输出错误。线上命令依赖运行环境中的 `lark-cli` 与用户登录，当前 Docker 镜像用于搬运服务，未包含该 CLI。
