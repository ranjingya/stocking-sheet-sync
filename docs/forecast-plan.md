# 老款需求预测实施计划

## 已确认规则

- 首版只计算老款通用预测，新品保留历史数据供人工填写。
- 当前观察窗口为预估日前30个完整自然日，按发货件数统计。
- 去年同期观察窗口为去年对应预估日前30天；去年后续窗口为预估日往前一年至预测截止日往前一年，包含末日。
- 商品季节读取 `std_api_jstbz_product_spec_info_f.labels`，按逗号拆分：夏款到当年8月31日，秋冬款到本销售季1月31日；四季款和标签缺失取下单日当天或之后最近的1月31日或8月31日。秋冬款1月下单截至当年1月31日，其余正常冬季下单截至次年1月31日。
- 跨季夏冬款不纳入首版自动处理；出现截止日早于预估日时标记待核对，不自动延长一年。
- 各平台分别按款式计算：去年后续周期量 × 今年近30天量 ÷ 去年同期近30天量。
- SKU占比默认采用本平台该款今年近30天销量。本次表内同款SKU数少于10且对应平台近30天销量少于20时，采用表内提供的全公司该款去年生命周期销量占比。兜底只替换占比，不替换平台需求总量。
- 款式总量按 SOP 向上取整到件，SKU默认四舍五入到件（0.5向上），差额优先调整到占比最高的SKU；并列按SKU编码排序，调整后非负且合计等于款式总量。
- 去年同期为零、历史数据不完整、全公司兜底无有效分母时，预估留空并记录原因；不自动加1。
- 预测不扣库存和采购在途。拼多多实退暂不处理。
- 系统预估与人工需求分列，原人工需求、公式及历史字段保留。

## 表格目标

全公司参考销量读取源表前部的去年生命周期列，保留原列及周期标题。老款每个平台有五项：今年近30天、去年同期近30天、去年对应后续周期、公式预估、人工需求。近30天现有列复用；已存在的其他历史指标保留，不能将日期不同的历史列当成同一指标。

## 实施步骤

1. **规则模块与外部配置**：实现季节识别、时间窗口、同比计算、占比兜底、取整与合计校验。补充边界测试，独立提交。
2. **数据读取与本地试算**：按需求表SKU读取主数据和标签；扩展指定历史区间查询；核验京东自营日出库的日期归属和重复维度；读取源表全公司去年生命周期销量及周期证据。输出计算依据、来源状态、日期和逐SKU结果。
3. **表格结构与填充**：补齐各平台新增字段，定位原人工需求列。历史开关控制历史列写入，预测开关控制预估列写入；预测可以读取历史作为输入。去年同期为零、公司兜底不可用时预估留空供人工判断；来源读取和结构异常仍走失败降级。
4. **测试副本验收**：使用真实老款验证日期窗口、数据来源、SKU分配、原内容保护、重复执行及强制重搬。核验完成后提交，不推送、不部署。

## 数据质量与待核验事项

这些属于技术核验，不替代已确认的业务规则：

- 同SKU历史记录及同款各SKU季节标签是否一致；多季节冲突进入待核对，不任意取一个。
- 标签缺失按四季；仅包含非季节标签也按季节缺失处理。
- 查询范围来自需求表商品行；主数据、季节、销量、同款汇总与占比分配均使用这些SKU。逐行处理查不到或身份有歧义的商品。
- 京东固定7、14、28、30、60、90天取截止日对应字段；其他周期累加 `outbound_yesterday`，要求完整日覆盖和同日条码唯一性。
- 全公司参考量来自表内去年生命周期销量；列缺失、歧义、数值不完整或合计为零时预估交给人工判断。
- 闰日往前年份映射到2月28日；观察窗口始终保持30个自然日。
- 历史已过截止日、缺失日期及主数据冲突均提供原因，不使用未经验证的数值。

## 验收标准

规则测试覆盖三个季节与空标签、跨年与闰年、阈值边界、零分母、同比下降、取整正负差额、多个款式和平台隔离。数仓试算提供真实证据，表格验证保护人工需求、公式、样式及其他部门内容。尚未验证的数据来源不启用自动预测。

## 当前实现状态

规则模块 `src/stocking_sheet_sync/forecast.py` 已实现上述周期、同比、占比兜底及分配校验，规则参数位于 `config/forecast.toml`。表内同款记录一部分季节为空、一部分为夏冬款时会报告冲突；空标签自身按四季处理，不隐式借用其他SKU季节。

`SalesReader.sales_window` 支持1至366天的出库明细区间，执行明细去重和逐日覆盖检查。京东预测读取器通过配置选择固定周期滚动字段，其他周期按日累加。

独立命令 `stocking-sheet-sync-forecast` 提供按需求表SKU或按款号的试算及JSON/CSV证据。报告区分 `ready`（可计算）、`manual`（人工判断，预估留空）和 `needs_review`（数据或身份异常）。使用方式见 [老款数仓预测试算](forecast-trial.md)。

`FILL_FORECAST_ENABLED` 接入表内SKU查询、公司生命周期销量读取、身份核对、市场部补列、计算数量写入及全量回读。人工需求和原公式保留。两项开关同时开启时填充三段历史量，只开预测时仅填预估结果。人工判断项允许其他有效数量继续填写；来源缺失或目标冲突时保留处理备份并交付原始表。实现与验收见 [公式预估填充](forecast-fill.md)。
